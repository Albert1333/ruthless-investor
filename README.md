# Злой инвестор

Тренажёр защиты стартапа за десять минут. Студент описывает проект, отвечает на **пять вопросов** инвестора Виктора Громова и получает оценку по **десяти критериям** с **тремя конкретными действиями**. После доработки можно пройти новый раунд и сравнить результаты.

Громов критикует бизнес-гипотезы, а не человека. Интерфейс и ответы инвестора — на русском. Приложение не требует собственной регистрации; доступ к размещённому экземпляру отдельно регулирует хостинг Sites.

## Режимы

- **Live AI:** сервер обращается к совместимому с OpenAI Chat Completions провайдеру. Нужны собственные действующие реквизиты.
- **Тестовый режим:** при отсутствии ключа работает явно обозначенный детерминированный адаптер. Он проверяет интерфейс и полный сценарий; его баллы не являются экспертной оценкой проекта.
- При ошибке подключённого AI приложение показывает ошибку и предлагает повторить запрос. Реальный ответ не подменяется тестовым вердиктом.

Оценка учитывает только питч и ответы. Даже точная цитата — заявление автора, а не независимо проверенный факт. Приложение не проверяет рынок в интернете и не является инвестиционной рекомендацией.

## Возможности

Сервер контролирует порядок действий и лимит в пять вопросов. Сессию можно восстановить после обновления страницы. Десять канонических критериев имеют фиксированные продуктовые веса; итог вычисляет код. Цитаты проверяются на точное совпадение с исходным текстом. После интервью доступны ровно три рекомендации и новый раунд. Входные данные валидируются, размеры запросов ограничены, повторная отправка защищена, rate limit хранится в общей базе.

## Архитектура

React + TypeScript strict, Next.js App Router через Vinext, Cloudflare Workers, D1, Zod и Lucide. Vinext выбран для развёртывания в Sites. Серверные модули используют Cloudflare bindings.

```text
app/                     страницы, стили и HTTP API
app/api/session/         создание и восстановление сессии
app/api/answer/          приём ответа и следующий вопрос
app/api/evaluate/        оценка завершённого интервью
lib/investor/            схемы, критерии, AI, хранение и переходы
db/                     Drizzle-схема D1
drizzle/                миграции базы
scripts/                сборка и локальный запуск
worker/                 точка входа Cloudflare Worker
.openai/hosting.json     конфигурация Sites, без секретов
docs/                   документация и материалы для жюри
```

Состояние в D1 не зависит от памяти одного серверного процесса. Подробнее: [архитектура](docs/ARCHITECTURE.md), [оценка](docs/SCORING.md), [безопасность](docs/SECURITY.md).

## Локальный запуск

Требуется Node.js 22.13 или новее и npm 11.6.2 (`packageManager: npm@11.6.2`). Команды выполняются из корня проекта. Используйте зафиксированный `package-lock.json`.

```sh
npm ci
npm run build
```

Перед первым запуском примените к локальной D1 каждую SQL-миграцию из `drizzle/` в порядке имени. Для каждого ещё не применённого файла:

```sh
npx wrangler d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_jittery_lord_tyger.sql
```

Замените `0000_jittery_lord_tyger.sql` на существующий файл. Не запускайте уже применённую миграцию повторно. Затем:

```sh
npm run dev
```

Откройте адрес, выведенный сервером, обычно `http://localhost:5173`. `npm start` проверяет готовую Worker-сборку локально. Данные находятся в игнорируемой `.wrangler/state`; это отдельная база от продакшена.

## Подключение настоящего AI

1. В кабинете выбранного провайдера создайте отдельный проект и серверный API-ключ; включите доступ к модели и установите лимит расходов.
2. Скопируйте `.env.example` в `.env.local`, замените заглушки своими значениями. Для тестового режима не создавайте файл с заглушкой ключа: ключ должен отсутствовать.
3. Укажите `LLM_BASE_URL` до `/v1`, без `/chat/completions`, и точный доступный `LLM_MODEL`.
4. Для локального Worker-preview скопируйте те же значения в игнорируемый `.dev.vars` и перезапустите сервер. Сервер читает Cloudflare env, затем process.env; `.env.local` подходит для запуска, передающего его в process.env. `.dev.vars` — надёжный путь для Wrangler.
5. В переменных окружения проекта Sites задайте эти же серверные значения, отметив ключ как secret, и выполните новое развёртывание.
6. Пройдите новый полный раунд и подтвердите режим живого AI и успешную проверку ответа.

| Переменная | Назначение |
| --- | --- |
| `LLM_API_KEY` | Секретный ключ, только на сервере |
| `LLM_BASE_URL` | HTTPS-адрес совместимого API до `/v1` |
| `LLM_MODEL` | Идентификатор модели у провайдера |
| `LLM_TIMEOUT_MS` | Тайм-аут попытки: по умолчанию 14000 мс, диапазон 1000–20000 мс |

Не используйте `NEXT_PUBLIC_*` для ключа и не вставляйте его в чат, питч, код или Git. Факт наличия адаптера не означает проверку настоящего запроса: см. [TESTING.md](docs/TESTING.md).

## Развёртывание

Основной путь — **Sites / Cloudflare Workers**. В `.openai/hosting.json` включён D1 binding `DB`; миграции входят в исходники. Sites собирает Worker, применяет миграции и хранит секреты отдельно. Сохраните существующий `project_id`, загрузите проверенную ревизию исходников, выполните сборку и публикацию. Проверьте успешный терминальный статус развёртывания.

Новые Sites по умолчанию приватны. Перед показом жюри отдельно настройте аудиторию и проверьте ссылку в другом браузере. Успешная публикация сама по себе не означает общедоступность.

**Vercel:** текущая сборка зависит от D1 и Cloudflare runtime. Прямой импорт как обычного Next.js-проекта не поддерживается. Сначала замените D1 на совместимое общее хранилище с атомарными блокировками и rate limit, переключите сборку на Next.js; затем импортируйте GitHub в Vercel, задайте серверные переменные и повторите все проверки. Основной артефакт рассчитан на Sites.

## Ограничения и сдача

Пользовательские API-ключи не предоставлены; настоящий AI-запрос не проверен. Без ключа доступен только test-адаптер. Текстовая оценка не подтверждает клиентов, выручку или рынок. Эвристики атак не гарантируют семантическую точность любой LLM. Анонимная сессия привязана к секретному идентификатору; потеря браузерного хранилища затрудняет восстановление.

Общая аналитика не собирается. Конверсия второго раунда и средняя разница баллов — предлагаемые метрики, не измеренные результаты.

Для сдачи нужны: проверенная ссылка с доступом жюри, публичный GitHub, подключённый и проверенный AI, [one-pager](docs/ONE_PAGER.md). [Демо-сценарий](docs/DEMO_SCRIPT.md) включает запасной план.
