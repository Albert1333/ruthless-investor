# Архитектура

## Граница ответственности

Браузер собирает питч и ответы, отображает прогресс и хранит идентификатор сессии для восстановления. Он не назначает вопрос, номер этапа, балл или признак завершения. Источник истины — запись в Cloudflare D1.

Worker проверяет запрос и допустимость перехода, получает текущую сессию, обращается к AI при необходимости и сохраняет результат. LLM предлагает содержимое вопроса или оценки; сервер проверяет его, задаёт фиксированные веса и рассчитывает результат.

| Компонент | Ответственность |
| --- | --- |
| React / App Router | Русский интерфейс, формы, результаты, доступность |
| Vinext | Next-совместимое приложение в Workers |
| Zod и серверная валидация | Проверка запросов, вопросов и оценок |
| AI-адаптер | OpenAI-совместимый HTTP-запрос, тайм-аут, ограниченный повтор |
| Детерминированный test-адаптер | Проверка полного сценария без оплаченного AI |
| D1 | Сессии, конкурентные изменения и общий rate limit |
| Sites | Версии исходников, сборка, секреты и публикация |

## API

| Запрос | Назначение |
| --- | --- |
| `POST /api/session` | Проверить питч, создать раунд, сформировать первый вопрос |
| `GET /api/session?id=…` | Восстановить состояние по секретному идентификатору |
| `POST /api/answer` | Принять ответ; после ответов 1–4 подготовить следующий вопрос |
| `POST /api/evaluate` | Оценить сессию с пятью принятыми ответами |
| `POST /api/question` | Повторить незавершённую генерацию вопроса после ошибки |
| `GET /api/config` | Получить режим работы без секретов |

Ошибки имеют безопасное пользовательское сообщение без ключей и внутренних ответов провайдера.

## Состояния и инварианты

Питч проверяется до начала интервью. После первого вопроса сервер ожидает ответ. Ответ принимается только для текущего вопроса; новый вопрос возможен лишь до пятого. После пятого ответа разрешается оценивание и переход в `COMPLETE`.

- Сессия содержит не более пяти вопросов и по одному ответу на каждый.
- Повторная доставка обработанного запроса не продвигает интервью второй раз.
- Конкурентные изменения защищены атомарной проверкой состояния в общем хранилище.
- Ошибка AI не выдаёт test-вердикт вместо живого.
- Повторное оценивание использует сохранённые пять ответов.
- Новый раунд создаёт отдельную сессию; сравниваются завершённые раунды.

Конкретные переходы и блокировки находятся в `lib/investor/`. Клиентская блокировка кнопок улучшает UX, но не заменяет серверные проверки.

## Данные

D1 нужен для общего состояния в serverless-среде: память процесса не сохраняет прогресс при смене Worker-экземпляра. Сессия содержит пользовательский текст, вопросы, ответы и результат. Текст передаётся выбранному AI-провайдеру в live-режиме.

Приложение не использует внешний поиск и не проверяет финансовые факты. Срок хранения, удаление и условия обработки у AI-провайдера необходимо определить перед широкой эксплуатацией; ограничения перечислены в `SECURITY.md`.

## Переносимость

UI и предметная логика используют TypeScript и React. Хранилище и runtime зависят от Cloudflare. Для другого хостинга нужен адаптер общего хранилища с атомарными операциями и повторная проверка ограничений; копирование файлов в Vercel само по себе не является переносом.

## Реализация модулей

`lib/investor/model.ts` содержит модели и критерии; `validation.ts` — проверки ввода; `scoring.ts` — проверку оценки и арифметику; `provider.ts` — AI и test-адаптер; `store.ts` — D1, TTL, lock/revision и rate limit; `service.ts` — переходы; `http.ts` — HTTP-обёртки и окружение. `GET /api/config` сообщает режим без секретов.

Сессии живут семь дней. Запись защищает блокировка на 65 секунд и сравнение ревизии; устаревший процесс не может перезаписать более новую ревизию. Лимиты запросов общие для D1. Обращение к AI делает максимум две попытки, по умолчанию по 14 секунд.
