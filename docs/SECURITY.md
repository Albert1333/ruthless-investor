# Безопасность и ограничения

## Секреты

`LLM_API_KEY` читается только сервером. Реальные `.env.local`, `.dev.vars`, локальная D1, кэши и служебное состояние исключаются из Git. `.env.example` содержит заглушки. У ключа нет переменной `NEXT_PUBLIC_*`; UI получает режим, а не реквизиты.

В production секреты задаются в окружении Sites и применяются новым развёртыванием. Не помещайте их в hosting manifest. Отдельный ключ и лимит расходов ограничивают последствия ошибки конфигурации.

## Недоверенный текст

Питч и ответы передаются как данные отдельно от системной роли. Они не должны менять персонажа, число вопросов, веса или этап. Сервер отклоняет некорректный ввод и явно инструкционные питчи. Ответы модели проходят структурную проверку; этап и итоговый балл задаёт код.

Фильтрация инструкций по шаблонам — эвристика, не полная защита от всех prompt injection. Семантическое качество требует проверки на выбранной модели. Даже корректный JSON может содержать спорную оценку; интерфейс показывает объяснения и исходные цитаты.

React отображает пользовательский текст как текст. Не используйте `dangerouslySetInnerHTML` или выполнение сгенерированного кода. Проверка цитаты подтверждает происхождение, но не истинность.

## Сессии и запросы

Случайный ID сессии — bearer-секрет: знающий его может получить соответствующие материалы. Не пересылайте его и не публикуйте URL API с ним. Восстановление использует серверное состояние, а не доверяет клиентским счётчикам.

D1 хранит общую запись и лимиты запросов. Атомарный контроль конкурентных изменений и идентификаторы операций препятствуют двойному продвижению. Размеры запросов ограничены, обращения к AI имеют тайм-аут и конечное число попыток. Ошибка возвращается без секретов и полного внутреннего ответа.

Rate limit не заменяет бюджетные лимиты, защиту периметра и мониторинг публичного сервиса. Пользователи за одним сетевым адресом могут разделять лимит. Доступ к экземпляру регулируется также политикой Sites.

## Данные

Текст сохраняется для восстановления и сравнения и передаётся настроенному AI-провайдеру в live-режиме. Не вводите персональные данные клиентов, пароли или секретные сведения. Условия хранения у провайдера зависят от сервиса и тарифа.

Не заявляется соответствие конкретному законодательному режиму или сертификация безопасности. Перед широкой эксплуатацией владелец должен определить срок хранения, удаление, бюджет, аудит доступа и правила обработки данных. Личного кабинета для управления всеми сессиями нет.

## Перед показом

Проверьте Git и клиентский bundle на секреты, сервер — на подмену этапа и повторную отправку. Пройдите раунд с реальным ключом и испытайте недоступность API. Убедитесь, что аудитория Sites соответствует назначению ссылки. Приватное развёртывание не является общедоступным.

## Конкретные пределы реализации

Сессия доступна семь дней с создания. При создании нового раунда выполняется ограниченная очистка до 100 истёкших сессий и до 100 старых rate-limit записей; физическое удаление всех истёкших данных не гарантируется ровно в момент истечения срока. Для строгого графика удаления нужен отдельный процесс обслуживания.

Rate limit: 20 созданий, 180 изменяющих операций и 600 чтений за час на SHA-256 от IP. Сырой IP приложение в D1 не сохраняет; хеш без соли всё равно не следует считать гарантированно анонимными данными. Без Cloudflare IP используется общий локальный bucket.

Блокировка сессии арендуется на 65 секунд. Каждая попытка записи проверяет ревизию. AI имеет не более двух попыток с тайм-аутом 14 секунд по умолчанию; настройка ограничена диапазоном 1–20 секунд на попытку.

GET восстановления передаёт session ID в query string. Само приложение его не логирует, однако журналы платформы могут записывать URL; их доступ и хранение требуют настройки. Защита API включает no-store, no-referrer, nosniff и проверку Origin для JSON-запросов, если заголовок присутствует.
